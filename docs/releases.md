# Flow（语流）发布总账

Flow 每一次发布都记在这里：**正式版**（语流，flowlang.cn）和**内测版**（flow.jasa.hk）。服务器和配置的改动另记在
[server-changes.md](server-changes.md)。

怎么读：

- **时间都是北京时间。** b9 以后的 tag 是 GitHub 上的机器打的，git 里显示 UTC，这里已经换算过。
- **tag（r26、b11）只在内部用。** 对学员、对 jasa.hk 的更新日志，按日期和内容称呼，不提 tag。内部一直叫「r27」的那批功能，
  实际的 tag 是 r26（见 r26 一条）。
- **提交**：「main `3e65d1a`」是 main 上的那个提交。2026-11-24 晚（#60）以后，装上去的是它的「构建提交」（加上发版时才生成的
  next.js、next.css 和指南 PDF，tag `build-<sha12>`），两个站装的是同一个构建。
- **自检**：发布后在那个网站上跑的端到端测试 `tools/qa_e2e.py`，用真实的 AI。「轻量」是 b10 起内测版自动发布用的那种，
  不把录音发给 AI。写法是「通过/总数」。AI 供应商偶尔超时，会让一两项没过，下面每次都写明是 AI 的还是程序的。
- **放行原话**：从 2026-11-24 起，正式版只在用户说「发正式版」这类话以后才发。那以前没有逐版放行的规矩，记的是当时最接近的那句话；
  找不到的写「没找到」。

## 怎么续写

- **内测版**：每次自动发布以后，`.github/workflows/beta.yml` 跑 `tools/changelog.py record`，把这一次（装了哪个提交、新合并的 PR
  和改到的区域、自检结果）追加到 `release-beta` 分支的
  [LOG.md](https://github.com/Jasame/Flow/blob/release-beta/LOG.md)。手工发的内测版，发完跑一次
  `python3 tools/changelog.py record b<N> --push`。
- **正式版**：发正式版的人（语流 2）在 `tools/deploy.sh <sha>` 之后：
  1. `python3 tools/changelog.py record r<N> --push`：自检结果趁还在 deploy-status 里记进 `release` 分支的 LOG.md；
  2. `python3 tools/changelog.py entry r<N>` 打出这次的草稿（PR、区域、自检、对应的内测版），放到下面「正式版」最上面，
     补上「学员能看到的变化」（一两句大白话）和「用户放行的原话」，有问题写进「出过的问题」；
  3. `python3 tools/changelog.py rows b<上次> b<这次>` 打出内测版表格的新行，贴到表格最上面；
  4. 只改 `docs/` 的 PR，CI 绿了自己合。
- 两个 tag 之间合了什么：`python3 tools/changelog.py draft r25 r26`（也可以写提交）。

## 流程和规矩的变更（新的在上面）

怎么发、谁来合、谁能做什么，每次改都记在这里，带上用户的原话。现行的完整规矩在 `tools/README.md`「发布顺序」。

- **2026-11-25 01:2x · 各区域会话可以自己给自己的 PR 开自动合并。** 语流 1 问「允许各区域会话在 CI 通过后自己给自己的 PR 开自动合并吗？」，
  用户答「允许」。用法：`gh pr merge <号> --repo Jasame/Flow --auto --merge`。规矩：
  - 只开自己的 PR；
  - 草稿和标了「先别合」的不开；
  - 开了以后留一句；
  - 正式版照旧只在用户说「发正式版」时才发。

  然后重启 flow-beta / flow」，不把整份备份拷回去。见 server-changes.md 开头。
