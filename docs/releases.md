# Flow（语流）发布总账

Flow 每一次发布都记在这里：**正式版**（语流，flowlang.cn）和**内测版**（flow.jasa.hk）。服务器和配置的改动另记在
[server-changes.md](server-changes.md)。

怎么读：

- **时间都是北京时间。** b9 以后的 tag 是 GitHub 上的机器打的，git 里显示 UTC，这里已经换算过。
- **tag（r26、b11）只在内部用。** 对学员、对 jasa.hk 的更新日志，按日期和内容称呼，不提 tag。内部一直叫「r27」的那批功能，
  实际的 tag 是 r26（见 r26 一条）。
- **提交**：「main `3e65d1a`」是 main 上的那个提交。2026-11-24 晚（#60）以后，装上去的是它的「构建提交」（加上发版时才生成的
  next.js、next.css 和指南 PDF，tag `build-<sha12>`），两个站装的是同一个构建。
- **自检**：发布后在那个网站上跑的端到端测试 `tools/qa_e2e.py`，用真实的 AI。「轻量」是 b10 起内测版自动发布用的那种，
  不把录音发给 AI。写法是「通过/总数」。AI 供应商偶尔超时，会让一两项没过，下面每次都写明是 AI 的还是程序的。
- **内测版发布的 run 页面**：Beta release 是 Tests 跑完才触发的（workflow_run）。GitHub 在 run 页面上显示的提交是触发那一刻
  main 的最新提交，不一定是装上去的那个；`beta.yml` 检出的是跑完测试的那个提交（`workflow_run.head_sha`），以 `b<N>:REQUEST`
  和 LOG.md 为准（2026-11-25 的 b83：页面上是 c4eacde，装的是 f907f2e）。
- **热修**：从上一个正式版的提交上挑修复发的版本（r34），不在 main 上；LOG.md 里写成「热修：…不在 main 上」，只列加上去的提交。
- **放行原话**：从 2026-11-24 起，正式版只在用户说「发正式版」这类话以后才发；11-25 11:15 起改成每晚 21:00 一次，用户点一次「发」。那以前没有逐版放行的规矩，记的是当时最接近的那句话；
  找不到的写「没找到」。

## 怎么续写

- **内测版**：每次自动发布以后，`.github/workflows/beta.yml` 跑 `tools/changelog.py record`，把这一次（装了哪个提交、新合并的 PR
  和改到的区域、自检结果）追加到 `release-beta` 分支的
  [LOG.md](https://github.com/Jasame/Flow/blob/release-beta/LOG.md)。手工发的内测版，发完跑一次
  `python3 tools/changelog.py record b<N> --push`。
- **正式版**：发正式版的人（语流 A1（原 2））在 `tools/deploy.sh <sha>` 之后：
  1. `python3 tools/changelog.py record r<N> --push`：自检结果趁还在 deploy-status 里记进 `release` 分支的 LOG.md；
  2. `python3 tools/changelog.py entry r<N>` 打出这次的草稿（PR、区域、自检、对应的内测版），放到下面「正式版」最上面，
     补上「学员能看到的变化」（一两句大白话）和「用户放行的原话」，有问题写进「出过的问题」；
  3. `python3 tools/changelog.py rows b<上次> b<这次>` 打出内测版表格的新行，贴到表格最上面；
  4. 只改 `docs/` 的 PR，CI 绿了自己合。
- **学员看的更新记录**（站内「我的 → 帮助 → 更新记录」，今日的「语流更新了」卡片）：`flow/corpus_data/updates.json`，
  每晚的正式版一条，20:00 以前由总账会话照这份总账写好、合进 main，语流 A1（原 2） 在 20:00 的清单里一起给用户看。
  写法见 `tools/README.md` 工作约定第 6 条：列全学员能感觉到的变化，每条一句话说清在哪里、怎么变了，改变用法的放进「用法变了」；
  只写真的上线的，不写 tag 和技术词。
- 两个 tag 之间合了什么：`python3 tools/changelog.py draft r25 r26`（也可以写提交）。

### 2026-11-25 · iOS 16.4 以前的 iPhone、iPad 打开语流停在「正在打开…」

整理自语流 A1 的事故笔记。用户约 22:15 确认「能打开了」，事故收尾。

- **现象**：在 iPhone、iPad 上打开 flowlang.cn，一直停在「正在打开…」，底部四个标签都在，内容出不来。Safari 和微信里都一样，
  换 4G/5G 也一样。安卓和系统新一些的 iPhone 都正常。
- **原因**：`flow/public/src/next/30-lookup.js` 第 1 行切句子的正则用了后行断言 `/(?<=[.!?]["”’]?)\s+/`，iOS/iPadOS 16.4 以前的
  Safari 不支持。iOS 上所有浏览器、微信内置浏览器用的都是同一个 WebKit，所以都一样。
  - 解析 `next.js` 时就报语法错，整份脚本一行都不执行，`next.html` 里写死的「正在打开…」和底栏就留在原地。
  - 报错收集也写在 `next.js` 里，所以这些设备连一条报错都发不出来。
  - 「接受用户协议以后打不开」是巧合，不是 r33 的协议改动引起的。
- **影响范围**：iOS/iPadOS 16.4 以前的设备完全打不开语流。这处写法 2026-11-22 前端按功能拆分时（`17e572a`）就在了，从那以后的
  每一版正式版和内测版都受影响，r32、r33 也一样。16.4 以前的 macOS Safari 理论上也受影响。已知受影响：一位老师的 iPhone 13
  （iOS 16.1.1），还有同学的老 iPad、iPhone。
- **怎么查出来的**（21:57 左右 A0 转来学员的报告，A1 牵头）：
  - 后台「页面报错」里没有这些设备的记录，和「脚本根本没跑」对得上；
  - 代码里，页面只靠一个 `next.js`，全前端只有这一处后行断言；
  - 香港 nginx 日志里，几台 iOS 16.1.1 的设备完整下载了 `next.js`（200，和同时段别的下载一样大），之后一次 `/api` 都没有，
    其中一台刷新了 11 次；同时段 iOS 17、18 的设备都正常；
